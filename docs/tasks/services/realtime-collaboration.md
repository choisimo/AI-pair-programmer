## TASK-101: Presence 프로토콜 설계
- **카테고리**: Realtime Collaboration
- **우선순위**: P1
- **예상 소요시간**: 3일
- **의존성**: TASK-017
- **담당 모드**: architect

### 설명
사용자 Presence(커서, 선택 영역, 입력 상태)를 전달하는 프로토콜을 정의하고 직렬화 포맷, 업데이트 주기, 충돌 해결 정책을 문서화한다.

### 체크리스트
- [ ] Presence 이벤트 타입 및 필드 정의
- [ ] 전송 채널(WebSocket) 프로토콜 설계
- [ ] 동시 수정 시 우선순위/락 정책 문서화
- [ ] 보안(인증 토큰) 포함한 프로토콜 스펙 리뷰 완료

### 수락 기준
- Presence 스펙이 `docs/prd/services/realtime-collaboration.md`에 반영
- 충돌 사례에 대한 시퀀스 다이어그램 포함

### 기술 노트
- 메시지 크기 최적화를 위해 Binary vs JSON 비교
- Phase 1에서 Presence만, Phase 2에서 CRDT 동기화 확장

## TASK-102: CRDT 편집 동기화 엔진
- **카테고리**: Realtime Collaboration
- **우선순위**: P1
- **예상 소요시간**: 5일
- **의존성**: TASK-101, TASK-014
- **담당 모드**: code

### 설명
문서 편집 충돌을 해결하기 위해 CRDT 기반 편집 동기화 엔진을 구현한다. 로컬 버퍼와 서버 동기화를 관리한다.

### 체크리스트
- [ ] CRDT 구조(예: Yjs 기반) 선택 및 커스터마이징
- [ ] 로컬 버퍼/네트워크 메시지 처리기 구현
- [ ] Latency 보정 및 오프라인 편집 재동기화 지원
- [ ] 단위 테스트 및 벤치마크 수행

### 수락 기준
- 3명 동시 편집 시 충돌 없이 동기화되는 데모 제공
- 이벤트 처리 지연이 150ms 이하 유지

### 기술 노트
- 초기에는 텍스트 편집 전용, 추후 구조화 데이터 확장 고려
- Telemetry로 동기화 지연 및 충돌 수 기록

## TASK-103: 실시간 이벤트 브로커 연동
- **카테고리**: Realtime Collaboration
- **우선순위**: P1
- **예상 소요시간**: 3일
- **의존성**: TASK-101, TASK-029
- **담당 모드**: devops

### 설명
WebSocket 게이트웨이와 이벤트 브로커(NATS, Redis Streams 등)를 구성하여 Presence/CRDT 메시지를 전달한다. 스케일링 전략과 모니터링을 포함한다.

### 체크리스트
- [ ] 브로커 선택 및 인프라 프로비저닝
- [ ] 게이트웨이 ↔ 브로커 연동 코드 작성
- [ ] 메시지 재시도/확인(ACK) 전략 구현
- [ ] 모니터링/알람 구성 및 문서화

### 수락 기준
- 브로커가 초당 1k 메시지 처리 시 안정적 동작
- 장애 발생 시 자동 재연결 및 알림 발송 확인

### 기술 노트
- Phase 1은 단일 리전, Phase 2에서 멀티 리전 고려
- 메시지 암호화/서명은 Security 정책(TASK-025) 활용

## TASK-104: 동시 편집 회귀 테스트
- **카테고리**: Realtime Collaboration
- **우선순위**: P1
- **예상 소요시간**: 3일
- **의존성**: TASK-102, TASK-103
- **담당 모드**: jest-test-engineer

### 설명
다수 클라이언트 동시 편집, 네트워크 지연, 패킷 손실 시나리오를 포함한 회귀 테스트 스위트를 구축한다.

### 체크리스트
- [ ] 시뮬레이션 환경 스크립트 작성 (Latency 50-300ms 범위)
- [ ] 충돌/분기/재연결 테스트 케이스 정의
- [ ] 테스트 자동 실행 CI 스크립트 구성
- [ ] 실패 시 상태 덤프 및 로깅 제공

### 수락 기준
- 테스트 스위트가 CI에서 주기적으로 실행되고 통과
- 충돌 발생 시 재현 가능한 로그와 지표 확보

### 기술 노트
- 테스트 프레임워크: Vitest + WebSocket Mock / Puppeteer 조합 고려
- Phase 2에서 멀티 파일 동기화까지 확장
