## TASK-109: 섹션 콘텐츠 IA 재정의

- **우선순위**: P1
- **예상 소요시간**: 2일
- **의존성**: TASK-041, TASK-049
- **담당 모드**: architect

Landing/Feature/Architecture/Code Demo 등 핵심 콘텐츠 섹션의 정보 구조와 사용자 여정 매핑을 재정의한다. 각 섹션의 목표와 핵심 메시지를 정리한다.

- [ ] IA 다이어그램 및 콘텐츠 맵 작성
- [ ] 사용자 페르소나별 콘텐츠 진입 경로 분석
- [ ] 문서 리뷰 및 PRD 업데이트

### 수락 기준
- IA 문서가 `docs/prd/services/content-sections.md`에 반영
- 각 섹션 목표가 제품 KPI와 연결되어 명시됨

### 기술 노트
- Phase 1에서는 개발자/리드/QA 페르소나에 집중
- 콘텐츠 변경 시 다국어 확장을 염두에 둔 키 구조 준비

## TASK-110: 동적 섹션 데이터 바인딩
- **카테고리**: Content Sections
- **우선순위**: P1
- **예상 소요시간**: 3일
- **의존성**: TASK-109, TASK-014
- **담당 모드**: code

### 설명
CMS 혹은 로컬 JSON 기반 데이터 소스를 섹션 컴포넌트에 바인딩하여 콘텐츠 업데이트를 코드 변경 없이 수행할 수 있도록 한다.

### 체크리스트
- [ ] 콘텐츠 데이터 스키마 정의
- [ ] 데이터 로더 및 캐싱 로직 구현
- [ ] 섹션 컴포넌트 데이터 바인딩 적용
- [ ] Storybook/프리뷰 환경에서 동적 콘텐츠 검증

### 수락 기준
- CMS/JSON 변경이 빌드 없이 반영되는 데모 제공
- Telemetry로 콘텐츠 로드 오류 감지 가능

### 기술 노트
- 초기에는 로컬 JSON → Phase 2에서 headless CMS 연동 고려
- `Data Access & State` 캐시 계층과 연동하여 재사용

## TASK-111: 코드 데모 상호작용 최적화
- **카테고리**: Content Sections
- **우선순위**: P1
- **예상 소요시간**: 2일
- **의존성**: TASK-110
- **담당 모드**: code

### 설명
Code Demo 섹션의 인터랙션(탭, 코드 스니펫, 실행 버튼)을 최적화하고 퍼포먼스/접근성을 개선한다.

### 체크리스트
- [ ] 코드 스니펫 하이라이트 및 복사 기능 구현
- [ ] 인터랙션에 대한 A11y 지원(키보드/스크린리더)
- [ ] lazy-loading 및 virtualization 적용 (필요 시)
- [ ] 사용자 행동 Telemetry 추가

### 수락 기준
- Lighthouse 측정에서 인터랙션 지표 개선
- A11y 점검에서 위반 사항 0건

### 기술 노트
- 코드 하이라이트는 Shiki/Prism 중 선택, 번들 영향 평가
- 데모 실행은 Phase 2까지 Stub, 실제 실행은 추후

## TASK-112: 콘텐츠 QA & 카피 가이드
- **카테고리**: Content Sections
- **우선순위**: P1
- **예상 소요시간**: 2일
- **의존성**: TASK-110
- **담당 모드**: documentation-writer

### 설명
콘텐츠 카피 가이드를 작성하고 QA 체크리스트를 마련하여 일관성 있는 메시지를 유지한다. 변경 프로세스를 정의한다.

### 체크리스트
- [ ] 카피 톤 & 스타일 가이드 작성
- [ ] 섹션별 QA 체크리스트 정의
- [ ] 콘텐츠 업데이트 워크플로(요청 → 리뷰 → 게시) 문서화
- [ ] 번역 대비 텍스트 리소스 키 매핑

### 수락 기준
- 카피 가이드가 위키/문서에 게시
- QA 체크리스트가 리뷰 프로세스에 통합

### 기술 노트
- 톤은 "전문적이면서 친근"으로 정의, 예시 제공
- 텍스트 리소스 키는 `i18n` 전략과 호환되도록 네이밍
