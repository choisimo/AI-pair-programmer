## TASK-049: 내비게이션 IA 설계
- **카테고리**: Layout & Navigation
- **우선순위**: P0
- **예상 소요시간**: 2일
- **의존성**: TASK-041
- **담당 모드**: architect

### 설명
정보 구조(Information Architecture)를 정의하고 주요 내비게이션 항목, 계층, 사용자 여정을 설계한다. 주요 사용자 시나리오별 진입 포인트와 컨텍스트 전환을 매핑한다.

### 체크리스트
- [ ] 내비게이션 트리 다이어그램 작성
- [ ] 사용자 여정별 클릭 흐름 분석
- [ ] Mobile/Desktop 반응형 구조 정의
- [ ] PRD 업데이트 및 리뷰 승인

### 수락 기준
- IA 문서가 `docs/prd/services/layout-navigation.md`에 반영
- 주요 시나리오별 3클릭 내 접근 가능 목표 명시

### 기술 노트
- `Realtime Collaboration` 뷰는 상위 탭으로 배치 고려
- A/B 테스트를 위한 내비게이션 변수 정의

## TASK-050: 레이아웃 컴포넌트 구현
- **카테고리**: Layout & Navigation
- **우선순위**: P0
- **예상 소요시간**: 3일
- **의존성**: TASK-049, TASK-042
- **담당 모드**: code

### 설명
헤더, 사이드바, 메인 콘텐츠 레이아웃 컴포넌트와 레스폰시브 브레이크포인트를 구현한다. Layout Context와 Breadcrumb, 탭 구성 요소를 포함한다.

### 체크리스트
- [ ] 레이아웃 그리드 시스템 구현
- [ ] 브레이크포인트별 레이아웃 전환 로직 작성
- [ ] Breadcrumb/탭 컴포넌트 연결
- [ ] 스토리북 및 스냅샷 테스트 생성

### 수락 기준
- 주요 뷰가 Desktop/Mobile에서 정상 렌더
- 레이아웃 전환 시 FOUC 없이 안정적인 애니메이션 확인

### 기술 노트
- CSS Grid + Flex 혼합 전략 사용 권장
- Layout 상태는 `Data Access & State` TASK-013 Context로 공유

## TASK-051: 반응형 브레이크포인트 검증
- **카테고리**: Layout & Navigation
- **우선순위**: P0
- **예상 소요시간**: 2일
- **의존성**: TASK-050
- **담당 모드**: code

### 설명
주요 브레이크포인트(320px/768px/1024px/1440px)에서 레이아웃이 깨지지 않는지 검증하고 개선 사항을 수정한다.

### 체크리스트
- [ ] Percy 또는 Chromatic 스냅샷 비교 설정
- [ ] 반응형 테스트 스크립트 작성 (Playwright Viewport)
- [ ] 문제 영역 수정 및 기록
- [ ] 검증 리포트 작성

### 수락 기준
- 모든 브레이크포인트에서 시각적 회귀 없음
- 리포트가 문서화되고 QA 승인

### 기술 노트
- Boomerang 레이아웃(열→행 전환) 시 높이 트랜지션 주의
- 다크 모드에서도 동일 검증 필요

## TASK-052: 사용자 워크플로 사용성 테스트
- **카테고리**: Layout & Navigation
- **우선순위**: P0
- **예상 소요시간**: 2일
- **의존성**: TASK-050
- **담당 모드**: project-research

### 설명
핵심 워크플로(코드 제안, 프로젝트 전환, 알림 확인)에 대한 사용성 테스트를 진행하고 개선 사항을 도출한다.

### 체크리스트
- [ ] 테스트 참가자 모집 및 시나리오 스크립트 작성
- [ ] 사용성 테스트 진행 및 녹화
- [ ] 개선 포인트 정리 및 우선순위화
- [ ] PRD/백로그 업데이트

### 수락 기준
- 테스트 보고서가 공유되고 승인된 개선안이 백로그에 추가
- 주요 워크플로에서 이탈률/시간 지표 기록

### 기술 노트
- 최소 5명 이상의 사용자 대상으로 테스트
- Cognitive Walkthrough와 System Usability Scale(SUS) 병행
